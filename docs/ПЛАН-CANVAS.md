# Переезд графа на canvas — план

Документ для новой сессии. Задача: заменить SVG-отрисовку графа на canvas, чтобы приложение
держало тысячи нод. Данные, физика и жесты по смыслу остаются прежними.

## Зачем

Замер на реальном файле КРОЛИКА (тестовый граф, 651 нода, 650 связей, окно стенда):
покой 1667 fps, панорама 1429, живая раскладка 60, нода в руке 58. Физика больше не узкое
место — упираемся в SVG: у каждой ноды 6–8 элементов, при 1500–2500 нодах браузер тормозит на
самой отрисовке, даже когда раскладка стоит. КРОЛИК это чувствует уже сейчас: «на тестовом
графе не плавно, чувствуются задержки».

Ориентир — graph view в Obsidian: canvas/WebGL (PixiJS), Barnes-Hut для сил, уровни детализации.
Наша физика уже даёт эквивалент Barnes-Hut (сетка соседства), отсечение по кадру есть. Не хватает
именно рендера.

## Железные требования КРОЛИКА

1. **Переключение и откат.** Старый SVG-рендер остаётся рабочим и включается настройкой.
   Сломалось — вернулся одной галочкой, без потери данных.
2. **Ничего не ломается и данные не теряются.** Формат файла не меняется вовсе: `S.graphs[].items`,
   `links`, `areas` те же. Никаких миграций. Обновление у других пользователей проходит незаметно.
3. Проверять на РЕАЛЬНЫХ данных (копия `data/planner.json`, только чтение), а не на синтетике:
   на синтетическом стенде я один раз намерил 11 fps там, где у КРОЛИКА 58 — потому что проставил
   область каждой ноде явно и получил 878 лучей принадлежности вместо восемнадцати.

## Что менять, а что не трогать

НЕ трогать: модель данных, `persist`, санитайзер, физику (`_tick` до блока отрисовки), остов
(`_остов`/`_вес`/`_ветка`), сетку соседства, лоток, правую панель, поп-ап ноды.

Менять только слой рисования: сейчас это `this.nodeEls` / `this.linkEls` (18 мест в `graph.js`,
файл ~200 КБ, 3000 строк) и всё, что зависит от DOM-элементов ноды.

## Что придётся переписать (это и есть объём)

- **Попадание мышью.** В canvas нет элементов: hit-testing по координатам. Нужен индекс —
  та же сетка (`_grid`/`_near`) годится. Учесть увеличенную зону захвата (сейчас невидимый круг
  вокруг ноды) и попадание по связи (`hitEls`).
- **Стили из CSS.** Цвета нод и связей, темы, свечение, пунктир «на паузе», серое кольцо,
  выделение, подсветка поиска, приглушение завершённых, шапка приоритета, формы по тегам
  (круг/квадрат/ромб/шестиугольник) — всё это сейчас в `styles.css` и должно переехать в код
  рисования. Значения тем брать из CSS-переменных (`getComputedStyle`), чтобы светлая тема и
  настройка свечения продолжали работать.
- **Подписи.** 651 текстовый элемент сейчас живёт всегда. На canvas — рисовать только при
  достаточном зуме (уровни детализации), иначе не рисовать вовсе.
- **Дуги связей** (`_recalcBends`/`_easeBends`/`_linkPath`) — геометрия остаётся, меняется только
  вывод: `quadraticCurveTo` вместо атрибута `d`.
- **Свечение «в работе» и серое «на паузе»** — уже рисуются на canvas (`_drawGlow`), это готовый
  образец, как смешивать слои.
- **Иконки тегов** (глифы шрифта Tabler) — на canvas это `fillText` тем же шрифтом; проверить,
  что шрифт загружен (`document.fonts.ready`), иначе первый кадр будет пустым.

## Порядок работы (каждый шаг заканчивается зелёными проверками)

1. **Замер «до» на копии реального файла** с окном РАЗМЕРА ОКНА КРОЛИКА (не стенда):
   покой / панорама / живая раскладка / нода в руке, при обзоре всего дерева и при работе вблизи.
   Записать в `docs/РЕШЕНИЯ.md` — с этими числами сравнивать каждый шаг.
2. **Каркас**: настройка `S.settings.graphRender` = `"svg"` (по умолчанию) | `"canvas"`,
   переключатель в настройках, canvas-слой рядом с `<svg>`. Оба рендера получают одну и ту же
   модель (`this.nodes`, `this.links`) и одну физику. На этом шаге canvas рисует только связи и
   круги — сравнить картинку и fps.
3. **Ноды целиком**: формы, цвета, состояния (готово/архив/в работе/на паузе/выделено/найдено),
   приоритет, галочка задачи, булавка, иконки тегов.
4. **Подписи с уровнями детализации** + отсечение по кадру.
5. **Интерактив**: наведение, клик, двойной клик, перетаскивание, рамка выделения, ПКМ-меню,
   попадание по связи, Alt-протяжка. Тут же — курсор и подсветка под курсором.
6. **Анимации**: «дыхание», плавный зум, FLIP-подобные переходы выделения, подсветка поиска.
7. **Проверки**: `tools/scenarios/граф.js` сейчас щупает SVG-элементы. Переписать так, чтобы
   проверялась МОДЕЛЬ (координаты, силы, состояния), а не разметка, и чтобы сценарий гонялся
   на обоих рендерах. Это важно: иначе canvas окажется без покрытия.
8. **Замер «после»** на той же копии и в том же окне. Ожидание: потолок уходит за десятки тысяч
   нод, подлагов на 650 нодах нет вовсе.

## Грабли, известные заранее

- **Плотность пикселей.** Canvas обязан учитывать `devicePixelRatio`, иначе на мониторе КРОЛИКА
  всё будет мылом. Образец — `_drawGlow`/`_drawBg`.
- **Порядок слоёв.** Сейчас: фон (canvas) → свечение (canvas) → SVG. Станет: фон → свечение →
  граф. Свечение вырезается из-под связей (`destination-out`) — при переносе не потерять.
- **Тема и `--glow`** меняются на лету (`applySettings`, `drawRetheme`): canvas обязан
  перечитывать цвета и перерисовываться, иначе останется в старой теме.
- **Пауза кадров.** Уже есть остановка цикла в покое (`_idle`/`_wake`) — canvas обязан её
  сохранить, иначе вернём 30 холостых кадров в секунду.
- **Экспорт/снимок графа**, если где-то опирается на SVG — проверить.
- **Не переносить в canvas лоток, поп-апы и панели**: они HTML и должны такими остаться.

## Как откатываться

Настройка `graphRender` переключает рендер без перезагрузки (пересоздать `Graph`). Данные общими
остаются в любом случае, поэтому откат — это именно переключение, а не восстановление файла.
Если canvas окажется хуже — SVG-ветка остаётся в коде до тех пор, пока КРОЛИК сам не скажет её
убрать.
