# Срочность: что горит прямо сейчас

Проект вычисляемой срочности и её показа в паутине (2026-09-01).
**Галерея:** `demo_срочность.html` в корне репозитория.
> **ВНЕДРЕНО 2026-09-01.** Рекомендуемый набор из этого документа уже в коде; ниже —
> обоснование и то, что осталось за бортом. Что именно сделано, перечислено в разделе
> «Что внедрено» в конце. Галерея остаётся песочницей: в ней можно посмотреть отвергнутые
> варианты, не трогая приложение.


---

## 1. Почему срочность обязана вычисляться

В рабочем графе 34 живых задачи. **Приоритет ненулевой у 9 из них** (0 → 25, 1 → 2, 2 → 7,
3 → ни одной за всю историю файла). **Срок стоит у 2 из 34.** Ручные флаги не проставлены и,
судя по 65 суткам истории, проставлены не будут.

Значит «что горит» нельзя прочитать из поля — это надо посчитать из того, что в файле уже есть:
даты, приоритета, статуса, давности правки и того, сколько работы висит на задаче.

Это ядро задачи. Рисование — вторая половина, и она бесполезна без первой.

## 2. Формула

Две чистые функции в `ui/js/core.js`, рядом с `dueLabel` / `dueBadge` (core.js:88-105):

```js
urgency(it, детей)      -> 0..1            // сырой балл, для сортировки
urgencyLevel(it, детей) -> 0 | 1 | 2 | 3   // «не горит / тлеет / греется / горит»
// «детей» — число незавершённых прямых детей-задач, НЕОБЯЗАТЕЛЕН (по умолчанию 0).
// Передаётся снаружи, чтобы функция не ходила по S.items: см. «Цена вычисления» ниже.
```

```
U = 0.55·СРОК + 0.25·ПРИОРИТЕТ + 0.12·ЗАСТОЙ + 0.08·ТЯНЕТ + СТАТУС
    (обрезается в 0..1)
```

### СРОК — вес 0.55

| дней до срока | вклад | почему |
|---|---|---|
| срока нет | 0 | нечему гореть |
| просрочено | 0,75 + 0,25·min(1, дней/14) | просрочка — **отдельная ступень**, а не продолжение шкалы: она начинается выше «сегодня» и растёт до потолка за две недели |
| сегодня | 0,75 | |
| завтра | 0,60 | |
| 2–3 дня | 0,45 | |
| 4–7 дней | 0,30 | |
| 8–14 дней | 0,15 | |
| больше 14 | 0,05 | не ноль: срок всё-таки есть, и при прочих равных такая задача важнее бессрочной |

**Почему 0,55.** Срок — единственный вход, который говорит о внешнем обязательстве, а не о том,
как человек себя чувствует по поводу задачи. Он должен перевешивать любую комбинацию остальных:
задача со сроком «сегодня» и нулевым всем прочим (0,41) обязана стоять выше задачи с приоритетом
2, застоем в месяц и десятком детей (0,33). На живых данных это ровно так и выходит.

### ПРИОРИТЕТ — вес 0.25

`(it.priority || 0) / 3`. Вес второй по величине, но приоритет проставлен у 9 задач из 34,
поэтому в реальном списке он работает как уточнение, а не как двигатель.

**Почему не больше.** Уровень 3 не использован ни разу; фактически шкала двухступенчатая.
Дать ей больше веса — значит построить срочность на поле, которое почти не заполняют, то есть
вернуться к тому, от чего уходим.

### ЗАСТОЙ — вес 0.12

Живая задача, которую давно не трогали: `(сейчас − it.updated)` в сутках.

| давность | вклад |
|---|---|
| меньше 7 суток | 0 |
| 7–30 суток | плавно 0 → 0,6 |
| больше 30 | 0,6 → 1,0, потолок на 60 сутках |

**Почему вес маленький.** У КРОЛИКА застой — норма, а не тревога: медиана «не трогали» у `todo`
равна 10,4 суток, максимум 55. Дай застою вес 0,3 — и наверх вылезет ветка
`Концепт → Модель → Риг → Анимация` (55 суток без движения), которая не горит, а просто ждёт
своей очереди. При весе 0,12 она получает 0,12 и остаётся внизу — где ей и место.

### ТЯНЕТ ЗА СОБОЙ — вес 0.08

`min(1, число незавершённых прямых детей-задач / 8)`.

**Почему так мало и почему прямые дети, а не всё поддерево.** Проверено обоими способами на
живых данных: при весе 0,15 и подсчёте по всему поддереву наверх выходят контейнеры
(`057_GK_CUP` с 17 потомками, `Team Presentation` с 16) и обгоняют единственную реально
просроченную задачу. Контейнер отвечает на вопрос «где горит», а не «за что садиться», поэтому
его влияние ограничено.

### СТАТУС — сдвиг, а не множитель

| статус | сдвиг | почему |
|---|---|---|
| `doing` | **+0,10** | начатое доделать важнее, чем начать новое |
| `next` | +0,08 | взято на этот заход |
| `todo` | 0 | |
| `waiting` | **−0,12** | ждём не себя: садиться за это нельзя, но срок продолжает тикать — поэтому понижаем, а не обнуляем |
| `paused` | −0,15 | сам отложил |
| `someday` | −0,20 | сам сказал «не сейчас» |

Статусы `next` / `waiting` / `someday` — из `docs/СТАТУСЫ.md`; пока их нет в словаре, ветки
просто не срабатывают, и формула работает на четырёх нынешних.

### Уровни

`urgencyLevel`: **3** при U ≥ 0,45 · **2** при U ≥ 0,30 · **1** при U ≥ 0,20 · иначе **0**.

Пороги подобраны по реальному диапазону, а не «поровну от единицы»: на живых данных максимум
U = 0,41, то есть **уровня 3 в файле КРОЛИКА нет ни у одной задачи**, и это честный ответ —
прямо сейчас у него ничего не горит по-настоящему.

### Цена вычисления

Функция чистая, без обращений к DOM и без разбора строк, кроме `parseYmd` на `due`.
**Зовётся в `build()`, а не в кадре:** 34 (или 947) вызовов раз в пересборку — доли миллисекунды;
те же вызовы в каждом кадре при 60 к/с — уже статья расхода.

Число детей брать из уже собранной иерархии (`build` и так проходит по всем элементам), а не
звать `childrenOfLive` на каждую ноду: иначе получится O(n²) — на 947 нодах это 897 тысяч
проходов по массиву.

## 4. Граница со сроком: две сущности или одна

**Отвечаю прямо: это две разные сущности, и на ноде они не дублируют друг друга — при условии,
что срочность не рисует собственных цифр.**

| | бейдж срока (`docs/СРОК-ВИЗУАЛ.md`) | срочность (этот документ) |
|---|---|---|
| отвечает на вопрос | **когда** | **за что хвататься** |
| источник | одно поле `it.due` | пять входов, включая `due` |
| когда виден | всегда, если срок есть — сейчас это 2 ноды из 34 | только у топ-N, максимум 8 |
| что показывает | точное число дней: «−6», «сег», «3» | ранг и жар: «эта в пятёрке» |
| место на ноде | верхний правый угол, r+9…10z | двойной контур / номер в очереди слева, r+8z |

Дублирование было бы, если бы срочность рисовала вторую цифру или вторую цветную шкалу времени.
Поэтому **срочность не получает своего числа дней и своей шкалы «зелёный→красный»**: у неё три
уровня жара (тлеет / греется / горит) на собственных цветах `--ur1..3`, начинающихся не с
зелёного, — «спокойно-зелёного» состояния у срочности нет по смыслу, она либо есть, либо нет.

На просроченной `Forest Project` встретятся оба признака: бейдж «−6» справа сверху и двойной
контур с номером очереди слева. Это не дублирование, а подтверждение: цифра справа говорит,
насколько просрочено, контур и номер слева — что задача попала в короткий список на сегодня.

**Отдельная страховка от путаницы (по замечанию КРОЛИКА).** Цвет верхнего уровня жара (`--ur3`)
и цвет просрочки (`--tm-over`) совпадают — обе палитры независимо пришли к одному и тому же
красному. На ноде одновременно просроченной и горящей это дало бы два похожих залитых плашки
рядом: слева и справа, но одного цвета. Позиции и так разведены, но чтобы не гадать, номер
очереди получил префикс **«№»** (`№1`, а не голая `1`) — срок всегда цифры без букв («3», «−4»,
«сег», «зв»), а ранг всегда буква с цифрой. Спутать их можно, только не читая.

## 5. Визуал: три уровня

### Уровень 1 — на самой ноде

Пять вариантов в галерее, все без `shadowBlur` и без анимации:

| вариант | читается на r=7 | в ч/б | цена в кадре | вердикт |
|---|---|---|---|---|
| **A · внешний ореол** (кольцо на r+14z, толщина по уровню) | да | да (толщина) | +1 список, +1 проход, **1 `stroke()`** на все горящие | **рекомендуется** |
| **B · свои связи горят** (линии от ноды толще и цветом жара) | да, даже лучше ноды | да | +1 проход по связям, их меньше, чем нод | **рекомендуется как дополнение** |
| **C · номер в очереди** (цифра 1..N в левом нижнем углу) | нет (LOD подписей) | да | +1 список, +1 проход `fillText` | берём вместе с A |
| **D · свечение (переосмысление)** | да | нет — свечение не имеет формы | новых проходов ноль | **отдельное решение, см. ниже** |
| **E · двойной контур фигуры** | да | да | +1 список, +1 проход | отклонён: путается с выделением (там обводка 4,5 и двойное свечение) |

**Рекомендация: A + C, с B как усилением в режиме «показать горящее».**

Обоснование в одну фразу на каждый: ореол на r+14z — самое дальнее кольцо, внутри него уже
всё занято (статус r+5z, булавка r+8z, бейдж срока r+9…10z), и он читается на мелкой ноде
толщиной, а не цветом; цифра ранга идёт в левый НИЖНИЙ угол — левый верхний занят левым концом
дужки приоритета (её сектор −144°…−36°), а справа сверху бейдж срока, справа снизу значок
статуса, снизу подпись — и она отвечает на вопрос «а с чего начать»
точнее любого оттенка; горящие связи не занимают на ноде ничего и работают именно там, где
нода мелкая, — на общем виде.

Полная карта занятых каналов ноды — единой таблицей в `docs/СТАТУСЫ-ВИЗУАЛ.md`,
раздел «Единая карта каналов ноды». Правишь радиус или угол — правь её тоже.

**Предел: не больше 8 горящих одновременно**, и только те, у кого U ≥ 0,20. Плюс защита от
вырожденности: если разброс баллов внутри верхушки меньше 0,02 — не подсвечивается ничего
(случай импорта, где у всех одинаковые нули). На живых данных подсветятся 4 ноды.

### Уровень 2 — на весь граф: режим «показать горящее»

Гашение непричастного **уже написано и работает** — `_drawMain`, graph.js:3795-3817:
множество `активные`, множитель `тень = 1 − (1 − ГАСН)·доля` и предикат `заметен(id)`, с плавным
переходом по 16 % за кадр. Сейчас `активные` заполняются из поиска или выделения.

Правка: третий источник — `this._горящие`. Ни одной новой строки в самом проходе отрисовки.

Одна поправка к константе: `ГАСН = 0.85` (непричастному остаётся 85 % яркости) выбрана для
выделения — «едва заметно ярче окружения». Для режима «что горит» этого мало: смысл режима в
том, чтобы всё остальное ушло. В галерее вторая константа — 0,55; обе показаны тумблером,
выбор за КРОЛИКОМ.

Включение: тумблер в панели графа рядом с поиском + горячая клавиша с модификатором
(одиночные клавиши отвергнуты, `main.js:381-385`).

### Уровень 3 — вне графа

**Это главное, а не украшение.** На 245 нодах срочная нода чаще всего просто **за кадром**, и
никакой ореол на ней не поможет.

1. **Указатели на краю кадра.** Треугольник в сторону горящей ноды плюс её название и номер в
   очереди — как маркеры целей в играх. В галерее это ползунок «Камера»: уводите граф вбок и
   смотрите на левый край. Цена: +1 проход по списку горящих (их максимум 8), обычные
   `moveTo/lineTo/fill` и `fillText`.
2. **Счётчик.** «горит: 5 · за кадром: 2» — в углу холста и/или в титлбаре окна.
   В галерее нарисован в углу кадра.
3. **Перелёт камеры к следующей горящей.** Механизм готов целиком: `_flyTo(n)` (graph.js:613-614)
   уже выделяет ноду и зовёт `_tweenView` — плавный ease-out на 520 мс (graph.js:4250-4260).
   Нужен ровно тот же цикл, что у поиска: `searchNext()` (graph.js:612) перебирает совпадения по
   кругу — «следующая горящая» это буквально та же строка с другим списком.

## 6. Отдельным пунктом: переосмысление свечения

Вариант D предлагает крупное изменение: **свечение перестаёт значить «в работе» и начинает
значить «требует внимания»**, а `doing` и `paused` уходят на кольцевой канал (туда, куда в
`docs/СТАТУСЫ-ВИЗУАЛ.md` уже переезжают `waiting` и `someday`).

**За:**

* свечение — самый громкий канал графа, и логично отдать его самому важному вопросу
  («за что хвататься»), а не справочному признаку («кто-то это делает»);
* новых проходов ноль: слой `_drawGlow` уже написан, ему меняется только источник списка;
* горящих по определению мало (максимум 8), а `doing` бывает у 11 нод — свечения станет меньше,
  а кадр дешевле.

**Против:**

* это смена значения знакомого признака: КРОЛИК полгода читает цветное свечение как «в работе»,
  и настройки свечения (`graphDoingGlow`, `graphDoingGlowRadius`, `Bright`, `Blur`) названы
  по этому смыслу;
* свечение не имеет формы — в ч/б оно только «светлее», то есть уровни жара им не передать;
* признак «в работе» останется без своего громкого канала, а он нужен: 4 из 7 нынешних `doing`
  — это то, что реально идёт прямо сейчас.

**Моя рекомендация — не трогать свечение сейчас.** Взять A + C + B, посмотреть неделю, и
возвращаться к вопросу, только если окажется, что ореол теряется. Решение крупное и
одностороннее: обратно смысл канала возвращать дороже, чем ввести новый.

## 7. План правки по адресам

### `ui/js/core.js` — сами функции

Рядом с `dueLabel` / `dueBadge` (core.js:88-105), потому что там уже живёт вся календарная
арифметика (`parseYmd`, `daysBetween`, `today`) и потому что `core.js` грузится раньше `graph.js`.


* **Вариант E — двойной контур** (заменил вариант A по итогам показа: КРОЛИК выбрал контур
  вместо дальнего кольца). Вторая обводка ПОВТОРЯЕТ ФОРМУ самой ноды (круг/квадрат/ромб).
  Зазор — **константа в экранных пикселях** (1,6 + 0,6 за уровень), а не доля от зума: первая
  версия множила зазор на `z`, и при увеличении контур разъезжался на десятки пикселей —
  «своя нода с усиленным краем» превращалась в парящую отдельно рамку (замечание КРОЛИКА после
  показа). Постоянный зазор держит контур вплотную при любом масштабе. Без свечения (жар — не
  doing/paused, ему не положен слой blur(30px)). **Только в режиме «что горит»**: раньше похожий
  признак появлялся от одной простановки срока и обводил ноду кругом, хотя от неё хотели только
  цифры. Срочность — ответ на вопрос «за что хвататься», и спрашивают его осознанно, по Ctrl+G.
* **Вариант C — номер в очереди**, слева от ноды (угол 160°), тоже только в режиме. **Плашка**
  с префиксом **«№»** (`№1`, `№2`…), а не кружок и не голая цифра: кружок с текстом переменной
  длины либо давил цифры теснотой, либо раздувался пустым полем — плашка (та же геометрия, что
  у бейджа просрочки, общий метод `_путьПлашки`) обтягивает текст ровно. Размер — тоже в
  экранных пикселях, от `ctx.measureText`, без `*z`: раньше радиус кружка скейлился зумом, а
  шрифт нет, и на сильном приближении бейдж раздувался, а на отдалении сжимался в точку, теряя
  сходство с текстом внутри. Зачем «№», а не голая цифра — разбор ниже, в «Граница со сроком».
* **Контур и номер видны при ЛЮБОМ отдалении**, не только пока нода крупнее порога деталей
  (правка по замечанию КРОЛИКА: «не видно номеров при сильном отдалении»). Тот же довод, что у
  дужки приоритета: горящих не больше восьми, и именно на общем виде, где всё остальное уже
  спрятал порог, нужно видеть, что вообще горит.
* **Задача на паузе никогда не горит** (правка по замечанию КРОЛИКА). Раньше пауза только
  понижала балл (−0,15), и задача с высоким приоритетом или горящим сроком всё равно могла
  попасть в «что горит», хотя её отложил сам человек. `urgency()` теперь возвращает 0 для
  `status==="paused"` безусловно — тем же способом, что для выполненной или удалённой задачи,
  а не скидкой в формуле.
* Режим «что горит» — кнопка с иконкой пламени в тулбаре графа (рядом с «Держать раскладку»)
