# Мыслик — правила работы

Личный планер: Python + pywebview (WebView2), фронт — ванильный JS в `ui/js/`.
Данные — `data/planner.json` рядом с приложением. Репозиторий: github.com/Krolik5555/myslik.

Файл читается автоматически. Он про то, КАК работать, а не про то, что умеет приложение
(это в README.md). Правило устарело — правь его в том же коммите, что и код.

## Порядок работы над задачей

Объяви класс задачи одной строкой в начале ответа — чтобы КРОЛИК видел, во что это обойдётся.

- **Правка** — понятно, что и где менять. Без субагентов: grep → Edit → проверка.
- **Разбор** — симптом ясен, причина нет. Сначала ВОСПРОИЗВЕСТИ и ЗАМЕРИТЬ, потом читать код.
- **Веер** (много агентов) — ТОЛЬКО по явной команде КРОЛИКА: «прочеши всё», «полный аудит».
  Сам не запускать и не предлагать: один заход дороже всей остальной работы за день. Уместен
  перед крупным релизом или когда баг не ловится разбором. Запуская — назвать цену заранее,
  4–6 аудиторов, проверка находок только для серьёзных.

Дороже всего обходится не сложная задача, а задача, сделанная дважды. Поэтому проверка перед
сдачей обязательна (см. ниже), даже когда правка выглядит тривиальной.

**Новая ТЕМА — новая сессия**, но начатую задачу не обрывать: продолжение дешевле, чем разбор
с нуля. **Баг не поддался с третьей попытки — остановиться и доложить замеры**, а не идти на
четвёртый слепой заход (доводка визуала по снимкам — не в счёт, там повторы нормальны).

## Инструмент вместо расспросов

```
python tools/dev.py status   версия, ветка, что не закоммичено и не запушено, список сценариев
python tools/dev.py check    версия в трёх местах, ?v=, компиляция Python, данные, модули фронта
python tools/dev.py run      все сценарии (или один: run полотно)
python tools/dev.py map      карта символов
python tools/dev.py shot     снимок окна или панели задач
```

Запускать питоном проекта — `.venv\Scripts\python.exe`: в системном нет `webview`, и `check`
с `run` падают на `ModuleNotFoundError`. Начинать работу с `status`, заканчивать `check` и
нужным сценарием. Приложение поднимается на демо-данных, живой `data/planner.json` не открывается.

**Нашёл баг — заведи на него проверку** в `tools/scenarios/`. Тогда он не вернётся молча, а
починка перестанет требовать ручного прогона по браузеру.

Если КРОЛИК описывает задачу коротко, достаточно трёх вещей: **где** (полотно / граф / захват /
отчёт), **что делает** (жест или действие), **что ожидает против того, что получает**.
Не хватает — спросить одним вопросом, а не гадать.

## Как искать причину

От дешёвого к дорогому, не наоборот:

1. **Воспроизвести в дев-режиме** и замерить через консоль браузера — один прогон возвращает
   десяток фактов и стоит копейки.
2. **Снимок экрана**, если вопрос визуальный (иконка, вёрстка, панель задач). Рассуждать о том,
   что видно глазами, дороже, чем посмотреть.
3. **Grep** — точечно, с контекстом в 20–40 строк.
4. **Сверка с чужим решением** — когда причина уже замерена, а вопрос в том, как её лечат
   другие (WebView2, pywebview, физика графа, полотно). Сначала issue, потом код: ответ
   мейнтейнера весит килобайты вместо репозитория. Читать один-два файла точечно, клонировать —
   по просьбе КРОЛИКА. Итог — строкой в `docs/ЗАИМСТВОВАНИЯ.md`, иначе изучим это заново.
5. **Чтение файла целиком** — последнее средство. `overlays.js` и `graph.js` — самые крупные
   файлы проекта, их целиком не читать почти никогда: точные размеры печатает `dev.py map`.

Не гадать: три «очевидные» гипотезы обычно дают по 2–9%, а замер показывает настоящее узкое
место с первого раза. Если решение звучит как «давай уберём проблемное место» — причина
не найдена.

## Правки

- **Только `Edit`.** Никаких heredoc-скриптов с экранированием: дважды приводили к тому, что в
  JS-строку попадал настоящий перевод строки, и файл переставал читаться целиком.
- **Поднимать `?v=` в `ui/index.html` СРАЗУ после правки фронта**, не в конце. Иначе браузер
  отдаёт старый код и чинится призрак.
- Комментарии — по-русски, объясняют ПРИЧИНУ («почему так»), а не пересказывают код.

## Проверка перед тем, как сказать «готово»

1. **`python tools/dev.py check`** — за один прогон: версия в трёх местах, поднят ли `?v=`,
   компиляция `app.py` и `ai.py`, целостность данных и синтаксис всех модулей фронта (каждый
   `ui/js/*.js` идёт через `new Function` — ловит ровно тот класс ошибок, из-за которого молча
   умирает целый модуль). Руками это же не повторять.
2. **Целевой сценарий** — то, ради чего правил, проверено вживую, а не «должно работать».
3. **Короткий регресс** — вкладки рисуются, окна открываются и закрываются, консоль чистая.

Дев-режим: поднять http-сервер на `ui/` и открыть `index.html?dev` (демо-данные, живой файл
не трогается). Реальное приложение: `python app.py`; `PLANNER_SELFTEST=1` откроет и закроет окно.

**Демо — не реальность:** стрелки полотна на схеме с одной связью выглядели правдоподобно,
а поломка вылезла на схеме с двенадцатью. Объёмы и висячие связи живого файла печатает
`dev.py check` (только чтение), масштаб воспроизводится в демо-сценарии. Разовых скриптов
поверх живого файла НЕ писать; не воспроизводится на демо — так и сказать: «проверено на
демо, на твоих данных проверь сам».

## Инварианты кода — нарушать нельзя

- `persist()` в `core.js` — ЕДИНСТВЕННАЯ воронка записи. Прямых `Store.save` быть не должно
  (исключение — `writeNow` и `flushSave` внутри самого `core.js`).
- `HasPy()` проверяет конкретный метод моста, а не объект `api`: pywebview создаёт `api` пустым
  и навешивает методы вторым скриптом.
- Скрипты в `index.html` — классические, порядок важен: core → model → views → graph → overlays
  → ai → report → main. ES-модули не использовать: приложение грузится по `file://`.
- У полотна СВОЯ история отмены (`_hist*` в `FlowEditor`). Глобальный Ctrl+Z туда не годится:
  он подменяет весь `S`, а редактор держит прямые ссылки внутрь `it.flow`.
- В `FlowEditor` имя `_snap` занято округлением к сетке — новые методы называть иначе.
- Иконку окна отдавать в `webview.start(icon=...)`: pywebview иначе берёт иконку из
  `sys.executable`, и кнопка на панели задач рождается с чужим значком.
- Даты: только через `makeDate()` с обратной сверкой. `new Date(y,m,d)` молча нормализует
  переполнение (29.02 → 1 марта).
- Методы `Api` в `app.py` не должны бросать исключения: наружу они уходят как отказ промиса,
  который в JS никто не ловит. Возвращать значение — `False`, `""`, `{"ok": False}`.
- Удаление мягкое: `deleteItem` не чистит `parent` у детей. Всё, что показывается человеку,
  считать через `childrenOfLive` / `linksOfLive`.

## Релиз

Только по явной команде КРОЛИКА. Порядок, нумерация версий и грабли — в
`docs/СБОРКА-И-РЕЛИЗ.md`, открывать ПЕРЕД началом: там снятие зависших процессов (иначе сборка
падает с отказом в доступе), путь к `gh` (в PATH его нет) и проверка запуска до публикации.
Рассинхрон версии в трёх местах ловит `dev.py check`.

Заметки к релизу — на языке пользователя: что стало работать, а не что поменялось в коде.

## Запреты

- **exe не пересобирать** без явной просьбы — только когда нужно передать сборку.
- **Не коммитить и не пушить** без просьбы (кроме шага релиза выше).
- **Не убивать чужие процессы.** У КРОЛИКА бывают открыты свои копии Мыслика и MCP-серверы на
  Python; закрывать можно только процессы, запущенные в этой сессии, определив их по пути.
- **Zapret не останавливать** ни при каких условиях.
- Не трогать `data/planner.json` руками. Тесты — на демо-данных или на КОПИИ.
