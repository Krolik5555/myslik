# Мыслик — правила работы

Личный планер: Python + pywebview (WebView2), фронт — ванильный JS в `ui/js/`.
Данные — `data/planner.json` рядом с приложением. Репозиторий: github.com/Krolik5555/myslik.

Файл читается автоматически. Он про то, КАК работать, а не про то, что умеет приложение
(это в README.md). Правило устарело — правь его в том же коммите, что и код.

## Первый ход — карта, а не поиск

**`docs/КАРТА.md` открывается ПЕРВОЙ по любому запросу**, до графа и до грепа. В ней таблица
«жалоба → адрес»: запрос звучит как «календарь всрато» или «плашка здоровая», а не именем
функции, и таблица переводит одно в другое за один ход. Быстрый вход — `dev.py где <слово>`:
печатает строки карты, символы кода и селекторы стилей, где слово встречается.

Карта врёт ровно тогда, когда её забыли поправить: меняешь код — правь карту в том же коммите,
особенно таблицу симптомов. Разошлась с кодом — верить коду и чинить карту.

## Пайплайн правки — граф встроен, а не «по желанию»

Подключён MCP `codebase-memory`, проект `E-ClaudeCode-planner` (1341 символ, 5224 связи).
**Чтение файла целиком — последнее средство.** Порядок обязательный, не рекомендательный:

1. **Где это в приложении** — `docs/КАРТА.md` или `dev.py где <слово>`.
2. **Где символ** — `search_graph`: отдаёт файл и номера строк вместо десятков килобайт текста.
3. **Радиус правки** — `trace_path` `inbound` (кто зовёт). **ОБЯЗАТЕЛЕН перед правкой любой
   функции**, кроме случая «символ заведомо один и вызывается из одного места». Правишь тело —
   сперва узнай, кто на него опирается: `head()` зовут пять видов, `persist()` — весь фронт.
   `outbound` — когда правка меняет то, что функция вызывает внутри.
4. **Тело функции** — `get_code_snippet`, а не `Read` файла.
5. **Правка** — `Edit` по строкам из графа. `Read` с `offset`/`limit` — только если нужен
   контекст вокруг, и ровно нужным куском.
6. **Перед выводом «такого в коде нет»** — `check_index_coverage`. Отсутствие в графе
   не доказывает отсутствия в коде.

`get_architecture` — когда модуль незнаком и нужна общая картина, а не конкретный символ.

### Где граф врёт — проверено замером 25.08.2026

- **Свежий код в индекс НЕ попадает сам.** `tagInk`, `fieldImgHeight`, `fieldAutoFit`, написанные
  за час до проверки, граф не знал вовсе: `search_graph` отдавал `total: 0`, хотя `detect_changes`
  видел 18 изменённых файлов. После `index_repository` все четыре нашлись с точными строками
  (узлов стало 1397 вместо 1341). **Правило: правил код в этой сессии — про СВОИ правки
  спрашивай Grep, а не граф; либо сперва `index_repository`.** Иначе получишь «такой функции
  нет» про функцию, которую сам же написал.
- **Диапазоны `parse_partial` ПЛАВАЮТ вместе с правками.** У `ui/styles.css` кусок был 1256–1295,
  после дня работы стал 1397–1436. Числа в голове держать бесполезно — смотреть `index_status`
  перед тем, как опереться на граф по этому файлу.
- **Шаблонные строки граф видит.** Разметка тут собирается строками, и вызовы вида
  `${tagInk(ts.color)}` внутри template literal он находит: `trace_path` дал 7 вызывающих,
  Grep — ровно те же 7. Занижения радиуса правки на этом месте нет.
- **Сверка стоит один ход.** `head()` — граф назвал 5 вызывающих, Grep нашёл 5 вызовов
  (и 2 упоминания в комментариях). Перед НЕОБРАТИМЫМ (снести символ, переименовать, «вызовов
  больше нет») граф подтверждать Grep'ом, а не верить на слово: `check_index_coverage`
  говорит о покрытии файла, а не о полноте связей.

**Граф НЕ используется** (идти сразу в Grep, не тратя ход): текст интерфейса, подписи,
комментарии, `styles.css` целиком, `.ps1`, JSON и данные, плюс куски из `parse_partial`.

`dev.py map` граф НЕ заменяет: `map` печатает состав файлов, граф — СВЯЗИ между символами.
`overlays.js` и `graph.js` целиком не открывать почти никогда.

## Порядок работы над задачей

Объяви класс задачи одной строкой в начале ответа — чтобы КРОЛИК видел, во что это обойдётся.

- **Правка** — понятно, что и где менять. Без субагентов: карта → `search_graph` → `trace_path`
  (кто зовёт) → `get_code_snippet` → Edit → проверка. Grep вместо графа — только для текста,
  подписей и стилей.
- **Разбор** — симптом ясен, причина нет. Сначала ВОСПРОИЗВЕСТИ и ЗАМЕРИТЬ, потом читать код.
  Граф здесь идёт ПОСЛЕ замера: он отвечает «где и с чем связано», а не «почему медленно».
- **Веер** (много агентов) — ТОЛЬКО по явной команде КРОЛИКА: «прочеши всё», «полный аудит».
  Сам не запускать и не предлагать: один заход дороже всей остальной работы за день. Уместен
  перед крупным релизом или когда баг не ловится разбором. Запуская — назвать цену заранее,
  4–6 аудиторов, проверка находок только для серьёзных.

Дороже всего обходится не сложная задача, а задача, сделанная дважды. Поэтому проверка перед
сдачей нужна даже там, где правка выглядит тривиальной — но ЗАПУСКАЕТ её КРОЛИК: проверки,
замеры и тесты идут только с его разрешения (см. «Проверка перед тем, как сказать „готово“»).

**Новая ТЕМА — новая сессия**, но начатую задачу не обрывать: продолжение дешевле, чем разбор
с нуля. **Баг не поддался с третьей попытки — остановиться и доложить замеры**, а не идти на
четвёртый слепой заход (доводка визуала по снимкам — не в счёт, там повторы нормальны).

## Инструмент вместо расспросов

```
python tools/dev.py status   версия, ветка, что не закоммичено и не запушено, список сценариев
python tools/dev.py check    версия в трёх местах, ?v=, компиляция Python, данные, модули фронта
python tools/dev.py run      все сценарии (или один: run полотно)
python tools/dev.py map      карта символов
python tools/dev.py shot     снимок окна или панели задач
```

Запускать питоном проекта — `.venv\Scripts\python.exe`: в системном нет `webview`, и `check`
с `run` падают на `ModuleNotFoundError`. Начинать работу с `status`, заканчивать `check` и
нужным сценарием. Приложение поднимается на демо-данных, живой `data/planner.json` не открывается.

**Нашёл баг — заведи на него проверку** в `tools/scenarios/`. Тогда он не вернётся молча, а
починка перестанет требовать ручного прогона по браузеру.

Вёрстку меряет `run вёрстка` — линейка, а не вкусовщина: содержимое шире своего блока, текст,
обрезанный без многоточия, вылезание за контейнер, наложение кнопок, разная высота полей в одной
строке. Гоняется на длинных данных (название без пробелов, шесть тегов, глубокий путь) и на узкой
правой панели — именно там раскладки и ломаются. Намеренную обрезку (`text-overflow:ellipsis`)
линейка за дефект не считает, у полей ввода прокрутка законна. Ширину ОКНА не подменять: `#topbar`
и `#body` считаются от окна, и сужение `#app` даёт ложные «уехало за край» на каждой вкладке.

Если КРОЛИК описывает задачу коротко, достаточно трёх вещей: **где** (полотно / граф / захват /
отчёт), **что делает** (жест или действие), **что ожидает против того, что получает**.
Не хватает — спросить одним вопросом, а не гадать.

## Как искать причину

От дешёвого к дорогому, не наоборот. Шаги 1 и 2 — это запуски, а значит спрашивать разрешение
перед ними обязательно; шаги 3–6 читают код и разрешения не требуют.

1. **Воспроизвести в дев-режиме** и замерить через консоль браузера — один прогон возвращает
   десяток фактов и стоит копейки.
2. **Снимок экрана**, если вопрос визуальный (иконка, вёрстка, панель задач). Рассуждать о том,
   что видно глазами, дороже, чем посмотреть.
3. **Граф символов** — `search_graph`, `trace_path`, `get_code_snippet` (см. начало файла).
   Отвечает на «где это и за что цепляется» за сотни токенов вместо чтения файла целиком.
4. **Grep** — точечно, с контекстом в 20–40 строк. Для текста, комментариев, подписей
   интерфейса и стилей — единственное средство, туда идти сразу, минуя граф.
5. **Сверка с чужим решением** — когда причина уже замерена, а вопрос в том, как её лечат
   другие (WebView2, pywebview, физика графа, полотно). Сначала issue, потом код: ответ
   мейнтейнера весит килобайты вместо репозитория. Читать один-два файла точечно, клонировать —
   по просьбе КРОЛИКА. Итог — строкой в `docs/ЗАИМСТВОВАНИЯ.md`, иначе изучим это заново.
6. **Чтение файла целиком** — последнее средство. `overlays.js` и `graph.js` — самые крупные
   файлы проекта, их целиком не читать почти никогда: точные размеры печатает `dev.py map`.
   Правя функцию, читать её кусок по номерам строк из графа, а не файл вокруг неё.

Не гадать: три «очевидные» гипотезы обычно дают по 2–9%, а замер показывает настоящее узкое
место с первого раза. Если решение звучит как «давай уберём проблемное место» — причина
не найдена.

## Правки

- **Только `Edit`.** Никаких heredoc-скриптов с экранированием: дважды приводили к тому, что в
  JS-строку попадал настоящий перевод строки, и файл переставал читаться целиком.
- **Поднимать `?v=` в `ui/index.html` СРАЗУ после правки фронта**, не в конце. Иначе браузер
  отдаёт старый код и чинится призрак.
- Комментарии — по-русски, объясняют ПРИЧИНУ («почему так»), а не пересказывают код.

## Проверка перед тем, как сказать «готово»

**Любая проверка, замер или тест запускается ТОЛЬКО с разрешения КРОЛИКА.** Сначала сказать
одной строкой, что именно предлагается запустить и что это покажет, — и дождаться ответа.
Правило распространяется на всё: `dev.py check` и `run`, запуск приложения и собранного exe,
разовые замеры, пробные прогоны «просто посмотреть». Молча гонять нельзя даже то, что кажется
безобидным и быстрым: решение о цене хода — за КРОЛИКОМ, а не за мной.

Отсюда и форма сдачи: работа доводится до конца, а список ниже идёт КРОЛИКУ как предложение
к прогону вместе с честной пометкой, что именно осталось непроверенным.

1. **`python tools/dev.py check`** — за один прогон: версия в трёх местах, поднят ли `?v=`,
   компиляция `app.py` и `ai.py`, целостность данных и синтаксис всех модулей фронта (каждый
   `ui/js/*.js` идёт через `new Function` — ловит ровно тот класс ошибок, из-за которого молча
   умирает целый модуль). Руками это же не повторять.
2. **Целевой сценарий** — то, ради чего правил, проверено вживую, а не «должно работать».
3. **Короткий регресс** — вкладки рисуются, окна открываются и закрываются, консоль чистая.

Дев-режим: поднять http-сервер на `ui/` и открыть `index.html?dev` (демо-данные, живой файл
не трогается). Реальное приложение: `python app.py`; `PLANNER_SELFTEST=1` откроет и закроет окно.

**Демо — не реальность:** стрелки полотна на схеме с одной связью выглядели правдоподобно,
а поломка вылезла на схеме с двенадцатью. Объёмы и висячие связи живого файла печатает
`dev.py check` (только чтение), масштаб воспроизводится в демо-сценарии. Разовых скриптов
поверх живого файла НЕ писать; не воспроизводится на демо — так и сказать: «проверено на
демо, на твоих данных проверь сам».

## Инварианты кода — нарушать нельзя

- **Графов несколько, и они НЕ пересекаются**: у каждого свои `items`, `areas`, `links`
  (`S.graphs=[{id,name,items,areas,links}]`, активный — `S.settings.graph`). Чтобы не
  переписывать сотню обращений, `S.items/areas/links` — НЕперечисляемые геттеры на активный
  граф (`graphBind`): в файл уезжает только `graphs`, без дубля. Общими остаются доски,
  картинки, теги и шаблоны — они адресуются по id. Санитайзер чистит КАЖДЫЙ граф
  (`_sanitizeGraph`), а множества id и уборка осиротевших досок/картинок — общие на все графы,
  иначе чистка одного графа снесла бы содержимое соседнего.
- У графа СВОЙ значок (`icon`, дефолт `GRAPH_ICON_DEF`) и цвет. Значок по умолчанию намеренно
  не `ti-affiliate`: этой иконкой отмечен вид «Заметки» в той же полосе, и два одинаковых
  значка подряд читались как дубль. Разделы полосы («Графы», «Области») отделены линией и
  каждый несёт свой значок — в свёрнутой полосе подписей не видно, и две кнопки «+» подряд
  иначе неразличимы. Правка графа — своим окном `openGraphEditor` (имя, значок, цвет, удалить),
  вызывается кнопкой «+» и правой кнопкой по строке графа.
- Переключение графа (`graphSwitch`) обнуляет историю отката: снимки сняты с прежнего графа,
  и Ctrl+Z после перехода подменил бы содержимое соседнего.
- **Стяжка физики считается ПО ОСТРОВУ** (`_остров` в `build`, применение — в `_tick`): у каждого
  несвязанного куска графа своя точка притяжения. Одна общая точка на весь граф означала, что
  никак не связанные деревья медленно съезжаются в кучу — стяжка линейна по расстоянию, а
  отталкивание падает как 1/d², на разлёте общий центр всегда перевешивает. Точку притяжения
  взвешивать теми же коэффициентами, что и силы, иначе остров начнёт дрейфовать (см. РЕШЕНИЯ.md).
  В ПАРЕ с этим: отталкивание УЗЛОВ между РАЗНЫМИ островами гаснет к нулю на `радиусы + 200 px`
  (и дальнее поле считается по островам). Одно без другого не работает — притяжение было
  единственным противовесом бесконечному отталкиванию, и без порога несвязанные деревья
  разъезжались без остановки. Порог мерился с обеих сторон: шире — деревья ползут врозь на
  обычном расстоянии, уже — перемешиваются (см. РЕШЕНИЯ.md). А вот расталкивание ПУЧКОВ между
  островами оставлено: без него положенные друг на друга деревья не расходятся, а сползаются.
- **В покой цикл кадров уходит, только когда ничего не движется** (`_tick`): к alpha, камере,
  жестам и `_hovId` добавлен `_навЕдет` — подсветка наведения доезжает В КАДРЕ (`n._нав`), и
  без этого признака уход курсора ронял граф в покой мгновенно (разгорание при этом плавное —
  курсор на ноде считается занятостью). Признак ПОДНИМАЕТ САМ `_hover` в момент смены цели, а
  снимает кадр, когда доехало: ставить его только по факту движения мало — условие покоя
  проверяется РАНЬШЕ отрисовки, к моменту ухода прошлая анимация уже доехала и флаг снят.
  На дереве больше 350 узлов (дыхание выключено) покойный кадр рисует ТОЛЬКО фон, `_drawMain`
  не зовётся вовсе — замер: 168 кадров/с под курсором против 6 кадров/с сразу после ухода,
  затухание двигалось скачками раз в 160 мс. Проверка в `граф.js` мерит на `graphDrift=0`:
  на дышащем дереве покойный кадр всё-таки полный, и баг из-под него не виден.
  Любая новая покадровая анимация обязана так же поднимать свой признак В МОМЕНТ ЗАПУСКА.
- **Длина нити «нода → область» живёт в НОДЕ** (`it.arealen`), а не в связи: сама связь в
  `S.links` не хранится, граф строит её из `it.area` на каждой сборке, и множитель в связи
  умирал бы при первом же `build`. У обычных связей длина остаётся третьим элементом `S.links`.
  Единица и мусор из данных срезаются санитайзером — хранить нечего.
- **Корзины НЕТ.** Удаление сразу насовсем (`deleteItem` = `hardDeleteItem`); вернуть можно
  откатом или кнопкой в тосте. Тяжёлое содержимое перед сносом уходит в карман удалённых
  (`trashKeep`/`trashRevive` в `core.js`), потому что в снимок отката оно не входит — иначе
  воскресшая нода вернулась бы без досок и картинок. Удаляют ПАКЕТОМ (`deletePack`/`restorePack`):
  вместе с нодами снимаются их связи, иначе возврат отдал бы ноды висящими в пустоте.
- `persist()` в `core.js` — ЕДИНСТВЕННАЯ воронка записи. Прямых `Store.save` быть не должно
  (исключение — `writeNow` и `flushSave` внутри самого `core.js`).
- `HasPy()` проверяет конкретный метод моста, а не объект `api`: pywebview создаёт `api` пустым
  и навешивает методы вторым скриптом.
- Скрипты в `index.html` — классические, порядок важен: core → model → views → graph → overlays
  → draw → ai → report → main. ES-модули не использовать: приложение грузится по `file://`.
- **Вендор доски (`ui/vendor/excalidraw/`) руками не правится и не пересобирается** без нужды:
  это собранный чужой код под MIT. Своя логика доски — только в `ui/js/draw.js`. Рецепт разовой
  пересборки (при обновлении версии) — в `docs/РЕШЕНИЯ.md`, node в проекте не заводить.
- **Полотно (`kind:"flow"`) = доска Excalidraw.** Своего редактора блок-схем больше нет, точка
  входа — `openFlowEditor` → `openBoard` в `draw.js`. Сцены лежат в `S.boards[id ноды]`, а НЕ
  внутри самой ноды: снимок отката сериализует `S.items` целиком, и рисунки раздували бы историю
  на каждый шаг. Удаление ноды обязано уносить её доску (`hardDeleteItem`), копирование в графе —
  копировать (`graph.js`, рядом с клонированием `it.flow`).
- **Старые схемы в `it.flow` НЕ трогать.** Они остаются как страховка и один раз переносятся на
  доску при первом открытии (`drawSeedFromFlow`), после чего доска помечается `fromFlow` и
  немедленно пишется. Без метки повторное открытие сконвертировало бы схему заново и затёрло
  нарисованное. Конвертация возможна только после `drawLoadLib()` и готовности шрифтов —
  в `sanitizeState` её быть не может, там вендора ещё нет.
- Доска грузится ЛЕНИВО, при первом открытии полотна: файл вендора весит мегабайты, на старте
  его тянуть нельзя. Закрытие обязано звать `drawDestroy()` — иначе React-корень остаётся жить
  в отсоединённом DOM (та же болезнь, что у графа). Между досками разных нод — только полный
  ремонтаж: публичный `updateScene` не принимает `files`, картинки чужой доски не подтянутся.
- **Доска открывается НА ВЕСЬ ЭКРАН** (слой `.draw-screen` в `#overlay-root`), и это не
  вкусовщина: Excalidraw сам переключается на телефонный интерфейс, если ЕГО контейнер уже
  730 px или ниже 500 px при ширине меньше 1000. Врезка во вкладке давала 937×493 — не хватало
  семи пикселей, и приезжала мобильная раскладка с плашкой внизу. Не возвращать доску во врезку.
- `render()` доску НЕ закрывает: её снимает только своя кнопка «Назад». Перерисовку зовут и
  навигация, и откат, и сохранение области — снос оттуда закрывал бы открытое полотно.
- **Щит клавиш стоит на `#draw-wrap` в фазе ВСПЛЫТИЯ, а не на `#draw-host` в capture.** React 18
  делегирует события на корневой контейнер, поэтому перехват «сверху вниз» глушил горячие клавиши
  самого Excalidraw: инструменты, Delete, стрелки. Проверка «клавиша r включает прямоугольник»
  в `tools/scenarios/доска.js` держит это правило.
- Ctrl+Z на доске гасится намеренно: глобальный откат подменяет весь `S`, а у доски своя история
  (как и у полотна).
- **Клавиши доски на русской раскладке живут мостом `drawLayoutBridge`** (`draw.js`): вендор ищет
  букву в `e.key`, с русской ему приходит «к» вместо `r`. Мост в фазе перехвата шлёт в ту же цель
  копию события с латинской буквой по `e.code`, оригинал глушит `stopPropagation` (без
  `preventDefault` — иначе отвалятся браузерные Ctrl+C/Ctrl+V; без глушения `Z` и `Y` сработают
  дважды). Поля ввода мост не трогает: там клавиша — буква, а не команда. Свои хоткеи Мыслика
  раскладки не боятся — они с самого начала на `e.code`, так и держать.
- Закрытие окна обязано звать `drawFlush()` ДО `flushSave()` (см. `appRequestClose` и
  `beforeunload` в `main.js`): между штрихом и крестиком лежат два дебаунса, и без этого
  последняя линия на диск не попадала.
- В `files` доски кладутся ТОЛЬКО картинки, на которые ссылается хоть один элемент. `getFiles()`
  отдаёт весь внутренний словарь и никогда его не чистит — иначе удалённое фото навсегда осталось
  бы мегабайтами base64 в `planner.json` и гонялось через мост при каждой правке любой задачи.
- **Содержимое ПОЛЕЙ ноды лежит вне ноды** (`fields.js`): картинка — в `S.media["m_…"]`, доска —
  в `S.boards["fld_"+id поля]`. Причина та же, что у полотен: снимок отката сериализует `S.items`
  целиком. Отсюда три обязанности — удаление ноды и поля уносит содержимое (`fieldsDrop`),
  копирование выдаёт НОВЫЕ ключи (`fieldsPack`/`fieldsUnpack`; общий ключ = два владельца одного
  холста), осиротевшее подметает санитайзер при загрузке.
- **Доска поля живая ТОЛЬКО во врезке, прошедшей `fieldBoardFits`** (ширина ≥1000 при высоте
  ≥180, либо ≥730 при высоте ≥500) — это тот же вендорский порог, что и у полотна. Уже — клик
  разворачивает доску на весь экран. Поднимается она сама, без клика, и клик по УЖЕ живой доске
  обязан гаситься: иначе всплывший от холста штрих пересобирает её заново. Пока не рисуют, во
  врезке лежит снимок `exportToSvg`, СВЕТЛЫЙ в обеих темах: тёмный режим доски это фильтр поверх
  холста, которого в снимке нет.
- Замеры размеров в полях делать И синхронно, И отложенно (кадр + таймер): у окна, которое не
  рисует кадров, `requestAnimationFrame` не приходит вовсе.
- **Живая доска в поле может быть только одна** (корень React в `draw.js` один). Снимать её
  обязаны все, кто уносит её узел: перерисовка панели полей, `renderAside`, закрытие ридера и
  окна правки — через `fieldsStopIn`. Плюс сторож на отсоединение узла как страховка.
- Панель полей одна на три места (окно правки, ридер, правая панель). Разницу задаёт `opts.save`:
  есть — правки пишутся сразу, нет — это черновик окна правки, и «Отмена» обязана его отменить.
- **Раскладка полей ДВУХУРОВНЕВАЯ, как в Notion**: строка делится на КОЛОНКИ, а внутри колонки
  плитки лежат ДРУГ ПОД ДРУГОМ. Одноуровневой («строка = плитки в ряд») не хватало на простейший
  случай: рядом с высокой картинкой помещалась одна плашка, а место под ней было мёртвым.
  Хранение плоское, порядок = порядок чтения, два флага: `br` — начинает строку, `st` — кладётся
  под предыдущим в ту же колонку. Поле без обоих открывает новую колонку, поэтому старые данные
  читаются без миграции. Ширина `gw` — доля строки и свойство КОЛОНКИ (у всех её плиток
  одинаковая, сумма в строке всегда 12), высота `gh` — пиксели самой плитки.
- Раскладку правим через `fieldsLayout` → операции над строками/колонками → `fieldsFromLayout`.
  Флаги руками по индексам плоского списка НЕ расставлять: так делала первая версия, и жест
  промахивался мимо задуманного места.
- Зоны броска: левая и правая четверть плитки — новая колонка с этой стороны, середина — выше
  или ниже цели В ЕЁ колонке, пустое место колонки — в конец колонки, промежуток между строками
  (и ниже последней) — своей строкой.
- У картинки высота плитки подгоняется под её пропорции ПРИ ВСТАВКЕ (`fieldFitImage`), а дальше
  едет за шириной постоянно: режим «по размеру» ВКЛЮЧЁН ПО УМОЛЧАНИЮ, и в данных хранится ОТКАЗ
  от него (`f.nofit`, кнопка `ti-aspect-ratio`, признак — `fieldAutoFit`). Хранить согласие
  нельзя: поля, вставленные до появления кнопки, навсегда остались бы с пустотами вокруг
  картинки. Пересчёт —
  пересчёт в `fieldsFitAuto` по загрузке картинки и по `ResizeObserver` на панели, БЕЗ
  перерисовки: она сносила бы живую доску на каждом кадре протяжки разделителя. Ширину для
  расчёта берут у САМОЙ ПЛИТКИ: узла `.fld-grid` в панели нет со времён переезда на колонки, и
  подгонка молча не срабатывала вовсе. Протяжка ручки высоты режим снимает — иначе жест молчал бы.
- Размер плитка получает ОТ ЧЕЛОВЕКА, а не от содержимого: высота — ручкой `.fld-grip` по
  нижней кромке (в поле лежит и текст, и картинка, и доска, а доска оживает только с
  определённого размера), ширина — разделителем `.fld-split`, включая концевой у правого края
  строки: без него ширину нечем править у плитки, стоящей в строке одна. Ужатая строка
  оставляет пустое место справа и помечается `gwm`; `fieldsNormalize` такую строку не
  растягивает — чинит только перебор долей и мусор, снимая тогда же пометку.
- Класс строки полей — `.flds-row` (не `.fld-row`: тот занят строкой дерева заметок).
- Шаблон хранит СОСТАВ и РАСКЛАДКУ полей: тип, название, `gw`, `gh`, `br`, `st`, `gwm`. Флаги
  обязан пропускать и САНИТАЙЗЕР шаблонов в `core.js` — он их срезал, и шаблон терял
  расположение при первой же загрузке файла, хотя сохранял правильно.
- Ctrl+V кладёт картинку во врезку ПОД КУРСОРОМ, а мимо врезок — заводит ей НОВОЕ поле в конце
  панели (`__полеПаста` на узле панели, помеченном классом `.fld-host`). Цель считает
  `fieldPasteTarget`: врезка под курсором → панель открытого окна (правка/ридер, курсор там
  неважен) → правая панель под курсором. В правой панели курсор нужен, но целимся во ВСЮ `#aside`,
  а не в узел полей: у ноды без картинок это полоска «Добавить поле» высотой в строку, попасть
  в неё мышью — задание на меткость. Дальше `#aside` не расширять: на холсте графа Ctrl+V занят
  вставкой скопированных нод. Над доской не встреваем вовсе (`fieldPasteNoGo`) — у
  Excalidraw своя вставка, а окно правки под полноэкранной доской никуда не делось.
  Слушатель `paste` — один на документ (`fieldPasteWire`), а не на врезке: врезка это div,
  фокус не принимает, и событие вставки до неё не доходит. Событие гасим (`preventDefault`),
  иначе картинка заодно уедет в поле ввода, если фокус был в нём. Фокус ради вставки забираем
  у полей ввода (текст вернёт `fieldPasteGiveBack`), но НЕ у `contenteditable`: возвращать
  текст туда нечем, и вставка пропала бы бесследно.
- Жесты плитки заняты и переиспользованию не подлежат: протяжка за любое место — переставить,
  ЛКМ по полосе — свернуть, двойной клик по названию или по тексту —
  правка, ПКМ — скопировать содержимое. ПКМ по общему описанию (`it.body`) делает
  то же самое во всех трёх местах — жест обязан быть один.
- Иконку окна отдавать в `webview.start(icon=...)`: pywebview иначе берёт иконку из
  `sys.executable`, и кнопка на панели задач рождается с чужим значком.
- Статусы ноды: `todo` / `doing` (в работе) / `paused` (на паузе) плюс отдельный `done`.
  «На паузе» — не задачное, а общее состояние (у КРОЛИКА проекты живут и заметками), и вид у
  него ТРЕТИЙ: завершённое глаз не цепляет вовсе, отложенное обязано быть видно и читаться как
  остановленное — серый пунктир, серое кольцо и слабый СЕРЫЙ блоб в слое свечения (цветной
  занят работой). Ставятся оба статуса как цвет: на ВСЁ выделение, если кликнутая нода в нём
  (`_setStatus` в `graph.js`), завершённым не меняются, повторное нажатие снимает.
- **Потухшее не бывает ни «в работе», ни «на паузе».** Своя завершённость есть только у задачи, а
  заметка и полотно тухнут ОТ РОДИТЕЛЯ (`_isFaded`) — и продолжали носить свой статус: завершённый
  проект светился паузным блобом изнутри. Признаки живой работы гасит `build` (`doing`/`paused`
  считаются с `!arch`), статус в ДАННЫХ остаётся — вернут ветку в работу, вернётся и пауза.
  Санитайзер держит и обратное: `done` ⇒ `status:"done"` (чужие данные приходят мимо `toggleDone`).
- Даты: только через `makeDate()` с обратной сверкой. `new Date(y,m,d)` молча нормализует
  переполнение (29.02 → 1 марта).
- **Срок ставится СВОИМ календарём** (`dueControlHtml` / `openDatePicker` / `wireDateControls` в
  `overlays.js`), нативного `input[type=date]` в проекте больше нет: он открывал системное окно
  WebView2 — чужие шрифты и синие акценты Chromium посреди монохромного интерфейса. Значение при
  этом не поменялось: рядом с кнопкой лежит СКРЫТОЕ поле с тем же `id="f-due"` / `data-f="due"`,
  той же строкой `YYYY-MM-DD` и событием `change` — на нём стоят и правая панель, и проверки.
  Попап живёт в `body` с `position:fixed`: внутри окна правки он уезжал бы вместе с прокруткой.
  Escape и клик мимо ловятся В ФАЗЕ ПЕРЕХВАТА и глушатся — иначе один Escape закрыл бы вместе с
  календарём всё окно, а клик мимо ушёл бы в подложку оверлея и закрыл его.
- **Про новую версию сообщает ПЛАШКА, а не тост** (`showUpdateBanner` в `main.js`). Тост живёт
  секунды и стирается следующим сообщением — отошедший от компьютера человек про обновление
  не узнавал вовсе. Плашка висит, пока не обновятся или не закроют её крестиком, и ход загрузки
  показывает В СЕБЕ (`applyUpdateNow(asset, ver, тихо)`): тост про «скачиваю» перебивался бы
  любым другим сообщением. Про одну версию говорим один раз за запуск (`_updNotified`).
- Методы `Api` в `app.py` не должны бросать исключения: наружу они уходят как отказ промиса,
  который в JS никто не ловит. Возвращать значение — `False`, `""`, `{"ok": False}`.
- Удаление мягкое: `deleteItem` не чистит `parent` у детей. Всё, что показывается человеку,
  считать через `childrenOfLive` / `linksOfLive`.

## Релиз

Только по явной команде КРОЛИКА. Порядок, нумерация версий и грабли — в
`docs/СБОРКА-И-РЕЛИЗ.md`, открывать ПЕРЕД началом: там снятие зависших процессов (иначе сборка
падает с отказом в доступе), путь к `gh` (в PATH его нет) и проверка запуска до публикации.
Рассинхрон версии в трёх местах ловит `dev.py check`.

Заметки к релизу — на языке пользователя: что стало работать, а не что поменялось в коде.

**КАЖДЫЙ релиз обязан обновить тур «что нового»** (`ТУР_ID`, `ТУР`, `ТУР_ДЕМО` в `main.js`).
Человек обновляется кнопкой, приложение перезапускается — и его встречает плашка снизу по
центру: номер версии и ОДНА строка о главном. Разбор открывается только по кнопке «Что нового»:
сразу вываливать демонстрацию нельзя, приложение запустили работать.

Формат разбора зависит от релиза: **новая функция** — шаг с подсветкой самой кнопки и стрелкой
к ней плюс наглядное сравнение (записи графа в `ui/media`, WebM/VP9, не GIF); **мелкие правки** —
просто списком, без демонстрации.

Показывается РОВНО ОДИН РАЗ: отметка `settings.tourSeen` (id тура = номер версии) встаёт в
момент показа плашки, а не при её закрытии — самый обычный исход тот, что человек увидел и
закрыл окно, ничего не нажав. Новая установка тур не видит вовсе: `boot` помечает его
просмотренным вместе с демо-данными, рассказывать новичку «что изменилось» не о чем.

**Описание ПРОШЛОГО релиза не остаётся.** `ТУР` переписывается целиком под текущее обновление,
старые клипы из `ui/media` удаляются. Иначе обновившийся человек читает про позапрошлую версию.
Открыть тур заново можно в графе: меню «…» → «Что нового». Проверки — `dev.py run тур`.

## Запреты

- **exe не пересобирать** без явной просьбы — только когда нужно передать сборку.
- **Не коммитить и не пушить** без просьбы (кроме шага релиза выше).
- **Не убивать чужие процессы.** У КРОЛИКА бывают открыты свои копии Мыслика и MCP-серверы на
  Python; закрывать можно только процессы, запущенные в этой сессии, определив их по пути.
- **Zapret не останавливать** ни при каких условиях.
- Не трогать `data/planner.json` руками. Тесты — на демо-данных или на КОПИИ.
